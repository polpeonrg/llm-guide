04 Model Selection Decision Tree
Ask These Questions First
Work through this before writing a single API call
1 — Is the task well-defined with a clear, narrow output?
Yes →
Single-step, structured output — classify, extract, translate, route
→ Start with HAIKU
No →
Involves writing, synthesis, reasoning, or multi-step generation
→ Continue to Q2
2 — Does the task involve novel problem-solving, deep analysis, or genuine uncertainty?
No →
Standard coding, writing, summarization, familiar domain work
→ Use SONNET
Yes →
Research, strategic planning, adversarial tasks, hard cross-domain reasoning
→ Continue to Q3
3 — Did Sonnet already fail, or is the task high-stakes enough to justify 15–30× cost?
No →
Try Sonnet first. You might be surprised.
→ Use SONNET, escalate if needed
Yes →
Sonnet failed, or the stakes clearly justify the cost and wait time
→ Use OPUS
05 Overkill in the Wild
Real Examples · Bad vs Good Choice
See the pattern. Build the instinct.
🎫
Support Ticket Routing
"Classify this customer message as billing, technical, or general inquiry."
❌ Over-selected
Using Opus — $0.015/1K tokens, 8 sec latency, 30× more expensive. The nuance here is zero.
✓ Right choice
Using Haiku — $0.00025/1K tokens, under 1 sec. Perfect for high-volume classification.
📧
Email Reply Draft
"Write a polite 3-sentence reply to this meeting request."
❌ Over-selected
Using Opus — maximal reasoning applied to a 3-sentence social task. Same output, 20× the wait.
✓ Right choice
Haiku or Sonnet — Haiku for templated, Sonnet if tone nuance matters. Both are instant.
🐛
Debugging a Function
"This Python function is throwing a KeyError. What's wrong?"
❌ Under-selected
Using Haiku — too shallow for code reasoning, may miss the root cause in non-trivial codebases.
✓ Right choice
Sonnet — strong code reasoning, fast, cost-efficient. Opus only if it involves deep system-wide logic.
🔬
Novel Research Synthesis
"Synthesize the latest findings on mRNA vaccine platforms and identify open research questions."
❌ Under-selected
Using Haiku or Sonnet — may miss nuance, conflate findings, or fail to identify genuine gaps in a complex field.
✓ Right choice
Opus — this is exactly where Opus earns its price. Deep domain reasoning, multi-source synthesis.

07 The Cheat Sheet
HAIKU
Reach for Haiku when…
↳ Task has a single correct output
↳ High volume (1K+ calls/day)
↳ Speed < 1 sec is needed
↳ Classify, tag, route, translate
↳ You've tested — it passes the eval
↳ Cost matters more than nuance
SONNET
Reach for Sonnet when…
↳ Code generation or debugging
↳ Writing with real quality bar
↳ Summarizing long documents
↳ You're unsure — default here
↳ Multi-step but familiar domain
↳ Production API, daily tasks
OPUS
Reach for Opus when…
↳ Sonnet already failed the task
↳ Genuinely novel problem space
↳ High-stakes: medical, legal, safety
↳ Deep cross-domain synthesis
↳ Strategic decisions with consequences
↳ Cost is irrelevant to the outcome

Adaptive Thinking — Cowork's Smart Toggle
Cowork includes an Adaptive Thinking feature (available on Sonnet 4.6 and Opus 4.6/4.7). When enabled, Claude automatically calibrates how much it thinks based on task complexity — simple questions get fast answers, complex ones get deeper reasoning, without you micromanaging it.
✓ Turn it ON when
You're unsure how complex the task is
You want the model to self-regulate
Tasks vary in depth within a session

It still uses more tokens than Haiku
Not a reason to always pick Opus
Model tier still matters — start with Sonnet
